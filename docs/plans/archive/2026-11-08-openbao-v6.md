**Goal:** Let an agent save or generate a development password once, then let the user find, reveal and copy it in Devkit, with the managed OpenBao foundation and scoped workflows required by the Lite guide.

**Specification:** [Devkit OpenBao Lite Implementation Guide](../Devkit_OpenBao_Lite_Implementation_Guide.md), plus the user's subsequent amendment: cleanup retention must be configurable, including no automatic cleanup. **Architecture:** Keep the standard-library Go CLI/backend, existing user-service conventions and embedded Vue/SwiftDesign frontend. One persistent OpenBao container and one restricted Devkit backend identity; CLI and dashboard call the same secrets operations. A small private JSON registry supplies stable resource identity and recoverable cleanup state; no new database or per-project/worktree AppRole system.

**Versioning:** This is the authoritative plan. [Archived v5](2026-11-08-openbao-v5.md) and its task records preserve the earlier design; v1–v4 remain in the archive. v6 replaces 12 implementation tasks with the guide's three milestones, removes grant-management/admin/upgrade-dashboard machinery and adds configurable cleanup. **Trust model:** one trusted development-host user, not hostile tenants. Backend project routes validate real resource ownership/context and cannot address system paths; operator settings/maintenance use explicit separate operations and browser authentication. One restricted OpenBao identity stays inside the backend and never reaches agent responses or child environments. No claim that same-user filesystem/Docker access distinguishes an agent from its human operator. Remove v5's per-project grant-management system and multiple service roles; do not weaken input validation, fail-closed reads or protection from accidental exposure.

**Scope boundaries:** manual unseal; no stored unseal/root key, auto-unseal, HA, new worker isolation, MCP, dynamic credentials, custom audit analytics or elaborate restore/upgrade UI. Existing local opt-out preserves local Devkit configuration; it does not introduce a second full project-secret/versioning backend. Show managed project-secret functions as unavailable when OpenBao is disabled. Existing installations migrate only through explicit verified import. Do not silently switch providers or fall back to old plaintext values.

## Shared behavior and interfaces

- `vault_client.go` owns the bounded OpenBao HTTP/KV adapter; `secrets.go` owns scope resolution and operations. Expose only typed operations, never a raw OpenBao path/API proxy. CLI reaches the same backend through a private local Unix socket; authenticated web handlers call the same operation layer. Reuse the user-service lifecycle; no separately hardened execution environment.
- Registry records installation/project/branch/worktree IDs, verified Git anchors/linkage, owned key paths and cleanup state/deadlines. Use a lock, atomic replace and generation checks; a small durable operation record resumes interrupted vault/registry changes. Names/tips/path reuse never transfer secrets. Missing paths or incomplete inventory are not proof of deletion; exclude temporary review checkouts. Explicit rebind preserves identity after verified external moves/renames.
- KV paths follow the guide. Worktree > explicitly linked branch > project precedence; detached worktree inherits project only without a verified branch link. Lists/history contain metadata, ownership and effective source, never values. Updates use expected version/CAS; overriding an inherited value writes to the chosen child scope. Avoid automatic KV version eviction within promised recovery windows; configure a bounded retention policy and refuse unsafe writes before silently destroying recoverable versions.
- CLI: `vault status/setup/unseal/ui/backup/health`; `secrets context/list/generate/set/get/update/rotate/delete/run/history/restore`; `secrets resources register/list/bind/reconcile/retire`; `secrets cleanup preview/status/restore/purge/config`; integration configure/status/reveal/rotate and Git binding; `agents skills install/status/repair`; `doctor --agents`. Each UI operation maps to one of these, with command help, metadata-only JSON, explicit selectors and sanitized errors. Values enter by protected prompt/stdin; reveal is explicit; generation never prints by default. `secrets run` injects only selected effective values and preserves child exit status/signals.
- Resource retirement changes secret metadata only, not Git/files. It previews exact owned keys and requires confirmation; active worktree links block branch retirement. Restore recovers secrets/registry and requires verified binding before normal context access; it does not recreate Git resources. Rotating a stored password does not change it in an application automatically; deleting a saved password does not revoke it remotely.
- **Cleanup settings:** host-level defaults are branch 7 days, worktree 7 days, project 30 days. Each retention accepts a positive duration or `never`; `automatic` can be disabled globally. Expose authenticated UI controls and `secrets cleanup config show/set` with `--branch-retention`, `--worktree-retention`, `--project-retention`, `--automatic on|off`. Validate bounds and show affected behavior before applying; no environment-only hidden setting.
- **No automatic cleanup:** do not automatically retire, soft-delete or purge secrets. Explicit retire/delete/restore and previewed, confirmed manual purge remain available. Confirmed retired secrets stay recoverable without automatic expiry destruction. `never` similarly prevents automatic expiry for the selected resource type. Do not delegate expiry to OpenBao TTLs that bypass these controls.
- **Deadlines:** normal retention starts at confirmed secret retirement, not an inferred Git deletion. Project retirement applies its selected retention to recoverable descendants and must not shorten a pre-existing longer/indefinite protection silently. Settings changes affect new retirements; retain existing deadlines as metadata while automation is off. Re-enabling automation requires an explicit preview/confirmation of any overdue batch before resuming its purge. No immediate hidden catch-up. Existing settings/deadlines survive restart and backup/restore. Backup retention is separate and may preserve deleted values.

## Milestone 1 — Managed foundation and Devkit credentials

**Goal:** persistent OpenBao is ready before credentials are collected; native UI works over private HTTPS and secrets survive restart/recovery.

**Create:** `cmd/devkit/vault.go` (managed lifecycle/config/setup), `vault_client.go` (HTTP/KV), `vault_backup.go` (scheduled encrypted backup), `integrations.go` (references/runtime delivery), `git_credentials.go` (accepted Git HTTPS/GitHub support), matching `_test.go` files; `tests/openbao_runtime_acceptance.py`.

**Modify:** `cmd/devkit/main.go`, `setup.go`, `hostconfig.go`, `proxy.go`, `share.go`, `auth.go`, `server.go`, `doctor.go`, `git_control.go` only for credential delivery; `bootstrap.sh`, `bundle.sh`, `docs/setup.md`, `docs/shares.md`. Keep Go standard-library-only.

- [ ] Pin/test a stable OpenBao image and persistent non-dev single-node Raft configuration. Start at 512 MiB limit, soft 0.5 CPU budget and monitored 1–2 GiB data estimate. Preserve existing volumes on reinstall/restart; refuse ambiguous initialization. Keep audit/storage private and protect swap/core dumps.
- [ ] Implement resumable provider setup, ready/sealed/unavailable health and manual human init/unseal without ordinary stdout/jobs/transcripts containing recovery material. Establish one least-privilege backend identity; keep native human admin separate and retire root after verification. Local recovery must not depend on web session signing, Cloudflare or Traefik.
- [ ] Add OpenBao references for Cloudflare DNS/share credentials, web-session signing and explicitly configured integration secrets. Collect only after readiness; preserve unrelated config. Verified import previews sources, compares private readback and tests consumers before switching references; remove only exact unchanged originals after confirmation. Never execute legacy command sources during discovery.
- [ ] Replace persisted DNS/tunnel environment values with private memory-backed file delivery supported by pinned images. Keep local ACME volume as sole Traefik-owned state, restrictive permissions and encrypted backup. Add exact vault TLS/private route and direct LAN split DNS checks. Test cold proxy start with a sealed vault separately from issuance/renewal; report limitations without a cached plaintext token fallback.
- [ ] Provide scheduled encrypted backups of Raft, registry/cleanup state when present, non-secret manifest and local ACME state. Use established encryption tooling, human-held recovery keys and a configured off-host destination; no bespoke crypto or administrative dashboard. Consistent ACME capture may briefly stop Traefik; disclose it and restart on failure. Restore procedure verifies an isolated restore and preserves IDs/permissions; snapshot alone is not a complete host backup. Never bundle unseal/decryption keys.
- [ ] Retain accepted generic Git HTTPS and GitHub token support: explicit repository binding to Git's helper protocol, exact host/port/path matching, project ownership checks and no fallback to stale helpers for vault-bound remotes. Keep unrelated/global helpers and SSH unchanged; no tokens in Git URLs/config/argv. GitHub API validation reports actual access; no GitLab-specific adapter, Git lifecycle expansion or Tailscale API automation. Project use cannot silently receive an operator integration token. Finish project-context binding with Milestone 2.

**Verify:** focused `go test ./cmd/devkit -run 'TestVault|TestIntegration|TestGitCredentials|TestSetup|TestProxy|TestShare|TestWebPassword|TestSession'`; `python3 tests/bootstrap_acceptance.py`; disposable runtime profiles for fresh/repeated setup, opt-out, sealed/reboot, migration interruption, token delivery, backup/restore and generic non-GitHub HTTPS/GitHub fixtures. Scan controlled sentinels in generated config, Docker inspect and logs. Probe actual LAN and remote Tailscale DNS/TLS/native login; mark unavailable external probes pending.

**Acceptance:** no reinitialization/data loss, no routine root credentials, no plaintext persisted consumer tokens, no sealed-vault fallback; manual recovery works independently; stored settings and certificate state restore successfully. Opt-out preserves existing local settings and clearly disables managed project-secret functionality.
