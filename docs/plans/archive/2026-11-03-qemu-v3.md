# QEMU support — version 3: explicit lifecycle control

Supersedes [v2](2026-11-03-qemu-v2.md). Preserves inventory, project grouping,
resource reporting, private connections and optional Fedora/Ubuntu prerequisites.
User selected existing project launchers plus native libvirt controls. Work stays
in the existing codex/qemu-dashboard worktree; execute as one agent.

## Behavior and acceptance criteria

- Extend a project `vms` selector with optional `control`: either shell `start` and
  `stop` commands, or `libvirt_uri` (qemu:///session or qemu:///system, UUID required).
  Optional timeout_seconds defaults to 120, accepts 1–600. Existing selectors are
  read-only. No disk provisioning, destruction, force-kill, public display exposure
  or implicit adoption of discovered guests.
- Commands: `devkit up --vm TARGET`, `start --vm TARGET`, `stop --vm TARGET`,
  `restart --vm TARGET`. TARGET is an exact configured name/UUID or opaque control ID
  from `vms`. Names/UUIDs resolve in the current recipe when present, otherwise among
  discovered recipes. `up` without --vm aliases Docker `live`; other existing Docker
  command behavior is unchanged. No implicit bulk VM actions.
- Launchers run sh -eu in the configured project root, with DEVKIT_PROJECT,
  DEVKIT_VM_NAME and DEVKIT_VM_UUID (and legacy DEVBOX equivalents). Launch must
  detach the guest and return; stop must gracefully shut down that exact guest.
  Script execution is trusted project code, like existing hooks. Commands are bounded
  and metadata/API never exposes their text or recipe paths. No sudo.
- Libvirt commands use the configured local URI and UUID only; start and shutdown,
  with read-only domstate probes. Restart is stop, wait, start. Errors/timeouts do
  not escalate to destroy or kill a guest. Missing domains remain unavailable.
- A host-wide nonblocking file lock serializes lifecycle operations across CLI and
  dashboard. Re-read config and live state under the lock. Duplicate claims (including
  same-project worktrees), duplicate VM identities, provider mismatch and incomplete
  process inventory block actions. Grouping alone is never control authority.
- Start/stop are idempotent. Wait for the observed requested state with a bounded
  timeout; process existence is VM startup, not guest OS/service readiness. A failing
  stop prevents restart. Record success only after verification; failures use existing
  history handling. Launcher timeout cancels the launcher process group (including shell children),
  never targets a discovered guest PID. Guests must detach from that group.
- Configured managed guests remain visible when stopped. Uncertain state is unavailable,
  never presumed stopped. API adds opaque control_id, actions and control_note; no paths
  or scripts. Existing discovery remains read-only. Authenticated dashboard buttons
  use existing action jobs, server-side lookup and CLI revalidation, independent of Docker.

## Limits and review focus

Existing project shell commands control their own storage and shutdown semantics: devkit
cannot make an arbitrary script graceful or non-destructive. Document the adapter contract.
Libvirt state must be verified after shutdown (it is asynchronous); see the official
[virsh reference](https://www.libvirt.org/manpages/virsh.html). External launchers can
still race devkit: identity checks and devkit locking prevent devkit's own duplicate
operations, but do not coordinate unrelated tools. No real user guests are used for tests.

## Verification checkpoint

Implemented the contract above. Full Go tests and vet pass; formatting and diff
checks are clean. Both real QEMU acceptance scripts pass. The lifecycle script
also drives authenticated HTTP jobs through the CLI into a real temporary QEMU
guest, checking cache invalidation, denied anonymous access, disk retention,
failed-stop protection and history. Libvirt lifecycle uses controlled virsh
fixtures; no real user libvirt guest was started or stopped.

Rendered fixture checks passed for state-dependent buttons, start/stop job flow,
post-job refresh, sign-out removing controls and no browser console errors. The
390 px viewport has no document overflow. The detector's five existing generic
panel-padding warnings remain unchanged; rendered VM rows are padded.

Review fixed two failure cases: unreadable process state can no longer be treated
as a stopped VM, and timed-out launcher children cannot continue mutating after
the lifecycle lock is released. A guest must detach from the launcher process
group; the adapter contract documents that requirement.
