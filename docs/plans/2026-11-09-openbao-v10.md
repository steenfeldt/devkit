## Contract

External apps call POST `/api/secrets/v1` using a Devkit bearer token. Dashboard cookie authentication stays unchanged. Tokens grant one fixed, registered project/branch/worktree context, including inherited reads, with explicit read/write/cleanup capabilities. Default read-only, 30-day expiry; explicit never is permitted. Tokens are random, stored only as hashes, named, listable and revocable through owner CLI. Deliver credentials once through a controlling terminal or an exclusively created private output file, never ordinary logs/listings. Token management cannot be delegated through the API.

Validate token expiry/revocation and live checkout/resource identity under the same secret-state lock as execution. Reject client overrides of the bound context, unrelated resources, host/operator actions, global cleanup settings, registration/binding and reconciliation. Worktree/branch tokens must not silently follow a checkout onto a different branch. Branch cleanup may run after Git switches away, but must still verify the original branch/ref identity. Cleanup applies only to the bound resource (project cleanup includes its children), retaining existing preview/confirmation, retention, off/never and active-branch checks. Reads/writes share existing CAS, paired entries and inheritance logic. Fail closed when sealed; no arbitrary command execution endpoint. Filter metadata to granted ancestry. Attribute external requests to token IDs without storing bearer values or secret payloads.

Accept bearer credentials only over HTTPS or direct loopback, reject browser Origin requests, bound JSON size and reject unknown/trailing JSON. Return no-store responses and fail invalid bearer requests without falling back to cookies. Keep token records outside vault backups: recovery to a new host requires fresh tokens; do not resurrect revoked credentials from a vault snapshot.

Native OpenBao access is documented separately at the existing private HTTPS `/v1/` endpoint, with OpenBao authentication and a separate app-owned KV path. Direct writes to Devkit-managed paths bypass its registry and are unsupported. User selected documentation of managed-vault access, not remote-vault configuration support.
