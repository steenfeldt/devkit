## Behavior and acceptance criteria

- Optional host `projects_dir` is an absolute or ~/ directory. Enumerate its immediate
  non-hidden, non-symlink subdirectories in name order, at most 128; do not recurse.
  Missing/unreadable directories and truncation produce visible warnings. Empty setting
  preserves existing discovery. Host config edits apply on refresh without restart.
- Every discovered directory appears even without Git or a valid recipe (Setup needed).
  Git common-directory identity groups the main checkout and linked worktrees, regardless
  of their location or creating tool. Keep Docker/harness/explicit vm_projects discovery.
  Deduplicate one repository reached from multiple sources. Independent clones stay separate.
- Projects is the new default dashboard tab, retaining existing tabs and saved selections.
  Expandable project rows show main checkout, branch, path, Git state, previews, worktrees,
  and VM rows grouped by the existing explicit project slug. Unassigned VMs stay in their
  inventory tab. Filter projects and preserve expansion on refresh. Use existing styling.
- Main checkout and worktree Docker launch uses `up` (existing live alias); require a Git
  checkout and valid live Compose recipe. Show Open/Start/Stop for existing previews.
  VM controls reuse opaque IDs, exact selectors, configured adapters and state-dependent
  actions. No implicit bulk starts, guest provisioning or weaker identity checks.
- Missing or truncated projects_dir discovery disables VM lifecycle controls until fixed,
  preserving conflict checks against unseen recipes. Default compose.live.yaml and the
  existing within-checkout Compose restriction apply to container launch capabilities.
- Discovery is read-only. Only explicit signed-in action requests execute recipes. Server
  revalidates discovered Git membership; arbitrary client paths are rejected. Existing VM
  config is reread at action time. Never return shell command text or VM disk paths.
- Project discovery remains usable if Docker fails, with a warning; VM inventory/actions
  remain independently usable. Recipes found through projects_dir discover stopped VMs.
