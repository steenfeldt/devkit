## Binding requirements and review focus

Already decided by the user-supplied handoff:

- Managed OpenBao is the fresh-install default; Local is an explicit opt-out. Existing installations require an explicit migration, never an automatic provider switch.
- Persistent production-mode OpenBao; never dev mode or reinitialization of populated storage. Start with 512 MiB memory, a 0.5-vCPU soft budget, and 1–2 GiB anticipated data, measured rather than advertised as sufficient.
- Keep `https://vault.devkit.<configured-domain>/ui/` and use the existing Traefik. LAN and remote Tailscale need trusted HTTPS and native OpenBao authentication.
- Store Devkit system and integration secrets in OpenBao once ready; only isolated authentication bootstrap material may remain outside. No root/unseal/recovery material in Devkit settings or agent output.
- Immutable project, branch and worktree IDs; worktree > linked branch > project precedence; explicit ownership and reveal; no system secrets for agents.
- Every UI action has a documented, scriptable CLI equivalent. CLI does not bypass backend authorization. Secret auditing uses a protected authenticated-actor audit stream; existing best-effort public history is insufficient and `DEVKIT_BY` is never an authority source.
- Branch/worktree deletion retains secrets for 7 days; project deletion gives all descendants 30 days. Restore before expiry, then destroy retained versions and metadata safely.
- Both Codex and Claude Code receive a canonical, versioned skill and preserved managed instruction blocks. Skills do not grant privileges.
- Preserve `devbox.json` and `DEVBOX_*` compatibility, existing previews/data, user edits, standard-library Go and committed `web/dist` assets.

Review focus, with owning tasks:

1. Same-UID agents, Docker access, writable service binaries, and project hooks can bypass token policies: Task 1 must prove the OS boundary before real system credentials are enabled.
2. A cold, sealed vault must not require Cloudflare, Traefik TLS or the vault-backed web session key to recover: Tasks 2–4 cover this circular dependency.
3. Name/path reuse, detached or temporary review checkouts, missing mounts and external Git operations must not rebind old secrets: Tasks 5–6 cover ambiguity and reconciliation.
4. Failed dual writes, version limits and cleanup/restore races must not destroy recoverable data: Tasks 5, 7 and 10 cover journals, CAS and virtual time.
5. Plaintext must not enter Docker configuration, job streams, public inventories, KeepAlive state or agent transcripts except intentional reveal/consumer output: Tasks 3–4, 7–9 and 12 test these boundaries.

## Proposed component boundaries and contracts

### Trust, transport and bootstrap

- Add `devkit secrets serve` as a long-running broker mode. Its trusted service installation, configuration and executable are not writable by workers. Bootstrap provisions the OS boundary; ordinary devkit commands never invoke sudo.
- Local operator requests use an operator-only Unix socket with kernel peer credentials; worker requests use a separate socket plus short-lived, project-bound grants, checked against peer identity and registry membership. A grant identifies actor, project, permitted resource IDs/operations, expiry and revocation generation; clients cannot choose their own authority by setting cwd, an ID, `DEVKIT_BY` or an environment variable.
- If workers run in VMs, use authenticated TLS transport to that same request handler instead of weakening socket authentication. Do not expose a generic OpenBao-path proxy or arbitrary privileged command endpoint.
- Separate broker roles: system integration access, per-project KV access, cleanup, and operator maintenance. Project requests select a pre-established scoped identity; they cannot request a system token. Runtime broker credentials cannot initialize, unseal, manage arbitrary policies, restore snapshots or generate root access. Root bootstrap is retired after restricted roles and independent native-UI human login are tested.
- Existing admin web actions, pairing, template saves and unrestricted host CLI are inaccessible to worker identities. Project code/Compose/Git hooks must run under the isolated execution path, even if a human starts them from the dashboard. Never make the trusted service execute a worker-writable binary on restart.
- Bootstrap and recovery are a distinct human-only control path independent of project credentials and the vault-backed web-session secret. Initial recovery material goes directly to a local controlling terminal or human-controlled encrypted ceremony, not stdout, JSON, jobs or a model session. Remote first-run UI authenticates via an operator-issued one-use pairing credential after host bootstrap; the wizard hands the actual recovery ceremony to that trusted channel. All remaining wizard steps have CLI equivalents.
- Human native OpenBao login remains separate from the Devkit browser cookie. Native administrative changes may drift Devkit-managed paths: report and reconcile, never silently grant or delete because a raw path appeared.

### Durable registry and provider behavior

Proposed state paths under the isolated service's configured state root (production default `/var/lib/devkit-secrets`, owner-only; tests use temporary roots):

```text
registry.json                 schema version + generation + resources + grants metadata
operations/                   durable non-secret migration/cleanup operation journals
backups/manifest.json          backup IDs/checksums/version/generation/destination metadata
openbao/data/                 persistent Raft storage, independent of previews
openbao/audit/                private audit sink with rotation
```

Runtime credential material belongs under an isolated memory-backed `/run/devkit-secrets/`, not the repository, normal settings, Docker environment or persistent generated files. Bootstrap identity material uses the selected protected service credential facility outside worker access. Backups never bundle recovery keys.

Registry schema v1 records random IDs from `crypto/rand`, kind, owner project ID, parent IDs, aliases, verified Git-common/admin-directory anchors, branch ref observations, checkout association, state, generation, timestamps, deadline and active references. Locators are evidence, never identity. Include an installation ID to detect copied/restored state. Keep preview IDs and the existing UI join keys separate.

Use an exclusive process lock, bounded reads, no-follow/pinned filesystem operations, generation checks and atomic write/fsync/rename for registry publication. No values in registry/journal; incomplete or incompatible state fails closed. Journals bridge registry/OpenBao/Git changes, because a JSON file and a remote KV write cannot be atomic together. Record intent before an external mutation and resume by operation ID/CAS rather than repeating an acknowledged mutation.

Identity rules:

- Explicitly enroll verified main and linked checkouts; list all local branch refs, including branches with no worktree. Never enroll discovery candidates automatically.
- Explicit rename/move preserves the immutable ID after preflight/revalidation. Recreated names get new IDs; clones and copied metadata are not automatically the same project.
- External branch rename/delete/recreate cannot always be distinguished by Git state or commit equality. Quarantine ambiguous associations and require operator reconciliation; do not infer inheritance from equal tips or names. A reused admin directory/path alone is insufficient.
- Detached HEAD inherits project only unless an explicit authorized association exists. Switching branches updates verified linkage while retaining worktree-owned secrets. Review scratch worktrees never acquire an automatic persistent scope or silently inherit the invoking branch's secrets.
- Missing directories, incomplete inventory or unavailable mounts do not prove deletion. Registry tombstones survive names being reused.

One key per KV entry, using the handoff's namespaces; encode validated key names and IDs, never accept caller-supplied mount/API paths. Use KV metadata for listing/history, CAS for changes, and separate explicit value reads. Source/owner/effective metadata is returned for every candidate, without plaintext. Pending-deletion ancestors deny descendant access; other-project IDs return an authorization failure without disclosing their metadata.

The Local provider uses the same authorization, registry, precedence, versions and cleanup contract with private local storage, clearly labeled **not encrypted at rest by OpenBao**. Do not invent custom cryptography. Selecting Local never exports vault values automatically. Missing legacy provider configuration retains existing behavior until an explicit migration; fresh setup records the default choice.

### Sensitive-setting migration and runtime consumers

| Existing material | Target / handling |
|---|---|
| `proxy.dns_env.*` file/env/command | `kv/devkit/integrations/<dns-integration-id>/<key>`; config stores an opaque reference. Legacy command sources are executed only by an explicit trusted migration, never discovery. |
| `share.token`, `share.token_file`, implicit `cloudflare-token` | Cloudflare share integration reference; preserve account/zone/domain/expiry settings. Never merge distinct DNS and Tunnel privilege scopes merely because values match. |
| Cloudflared tunnel credentials | Protected runtime token-file delivery; retain resource IDs and expiry metadata only. Re-fetch from the authorized integration when needed; never persist the token in Docker configuration. |
| `web-secret` | `kv/devkit/system/web-session-signing-key`; deliberate session invalidation on cutover/rotation. Do not regenerate a local key when vault-backed lookup fails. |
| `web.password_hash` | Keep salted verifier as explicit non-plaintext authentication metadata in protected settings. Raw password is never stored. Recovery must not depend on session signing availability. |
| T3 pairing / harness-managed auth | Preserve direct transient responses; no takeover of T3 credential storage. Agent API/subscription credentials are outside Devkit ownership unless explicitly configured as integrations. |
| Traefik ACME private keys | Under recommended D6, store the versioned ACME state in `kv/devkit/system/proxy-acme-state`, restore to protected tmpfs and checkpoint renewals. Migrate/retire the legacy certificates volume only after verified readback and explicit approval. A permanent volume exception requires an explicit requirement amendment. |

Migration stages: preview selected sources/consumers without values → checkpoint original non-secret schema and source ownership → read selected source privately → write target with CAS → compare readback in memory → test consumer → atomically switch reference → restart/reload relevant consumer → re-test → explicitly approve retirement of exact unchanged legacy sources. A source modified concurrently is retained and flagged. Never delete externally managed env/command secrets. Retain an encrypted rollback artifact until acceptance; no new plaintext backup of credentials. Scan known generated configs, Compose overrides and Docker configurations with sentinels, not users' entire home directory. Do not promise secure erasure from SSDs or old backups; recommend credential rotation where old plaintext copies existed.

For managed Cloudflare DNS, replace value environment variables with lego `_FILE` references to private tmpfs-backed files mounted read-only. Handle refresh and consumer reload explicitly; some consumers read credentials once. On reboot the runtime directory is empty and vault-required consumers wait for unseal. Never carry previous plaintext across a reboot as fallback. An already running consumer may retain a previously delivered value in memory; new broker fetches fail closed and status must distinguish this from a vault read succeeding. Validate each other DNS provider's file-input support rather than assuming all custom names support it. Unsupported safe delivery blocks managed setup for that provider and reports the exact limitation.

`secrets run` injects only selected authorized effective values into the child process, does not print them, strips broker/OpenBao/system authentication from the child environment and preserves exit status/signals. It cannot prevent the child from printing values. Compose integration uses reference-only saved configuration and runtime secret files; never resolve plaintext into `<common>/devkit/runs/*/compose.json`, build args or image layers. Rotation does not automatically rotate a remote database password: adapters must perform and report the remote change or label the operation as stored-value rotation.

### CLI and UI parity contract

Every new family has command-specific help, metadata-only `--json`, strict selectors, typed errors and bounded input. Retain existing CLI exit conventions for old commands. New management commands use 0 success, 1 operational/typed failure, 2 usage; JSON errors expose stable `code` plus sanitized message (`forbidden`, `not_found`, `sealed`, `unavailable`, `conflict`, `pending_deletion`, `expired`, `invalid_scope`). `secrets run` propagates the child exit code after successful launch. Plaintext requires `--reveal`; it is never implicit in `--json`.

## Execution tasks and dependencies

Tasks below are pending implementation. For code tasks, first add the named behavioral tests, run the focused command to observe the intended failure, implement the smallest passing change, and run the focused verification plus any affected existing regression. Do not regard a test filter matching no tests as success. They are grouped under the original five implementation phases; prerequisite security, minimal registry and KV work move earlier where first-run readiness depends on them. ### Task 1 — Establish the enforced execution boundary (Phase 1 prerequisite)

**Goal:** Prove one isolated project agent/job can use a synthetic scoped broker credential while host/system/other-project access is denied, before enrolling real credentials. Re-run this boundary against real OpenBao after Tasks 2/7 and before migration cutover.

**Files:** create `cmd/devkit/secrets_broker.go`, `secrets_auth.go`, `agent_runtime.go`, matching `_test.go` files, and `tests/openbao_isolation_acceptance.py`; modify `bootstrap.sh`, `cmd/devkit/setup.go`, `doctor.go`, `actions.go`, `preview.go`, `run.go`, `git_control.go`, `docs/setup.md`, and ADR 0013.

**Steps:**
- [ ] Resolve D1. Use an in-memory synthetic provider for this initial boundary proof so it does not depend on later KV/registry implementation. Add a versioned broker request/response envelope and kernel-authenticated operator/worker routes; do not trust flags or cwd as identity.
- [ ] Provision distinct protected service state/executables and one worker execution adapter. Route project hooks, builds, Git hooks and agent tools through it; keep Docker/control-plane privileges out of workers. No new arbitrary host-exec service.
- [ ] Run a representative project preview/test through the worker before broadening agent integrations. Probe file access, socket access, spoofed UID/grants/context, `/proc` environment access, privileged/host-network Compose requests and host Docker access with synthetic credentials.
- [ ] Retain existing operator workflow only where it cannot be reached by workers. If T3 cannot launch the selected isolated adapter, stop this task with evidence and revise the architecture; do not claim a config-only boundary.

**Acceptance Criteria:** authorized project call works; system and second-project reads fail at transport/policy level; ignored instructions do not bypass denial; privileged project-supplied hooks cannot access operator state; worker cannot replace trusted code; legacy preview acceptance still works on its intended supported path.

**Verify:** `go test ./cmd/devkit -run 'TestSecretsAuth|TestSecretsBroker|TestAgentRuntime'`; `python3 tests/bootstrap_acceptance.py`; opt-in `DEVKIT_OPENBAO_RUNTIME_TEST=1 python3 tests/openbao_isolation_acceptance.py` using an explicitly selected disposable host/worker. Capture successful and denied operations without values. This is a real security gate, not satisfied by mock tests alone.

### Task 2 — Managed service, bootstrap and recovery path (Phase 1)

**Goal:** Provide a resumable persistent vault lifecycle before any integration credential is requested.

**Files:** create `cmd/devkit/vault.go`, `vault_setup.go`, `vault_client.go`, `vault_config.go`, `vault_backup.go` (backup foundation), corresponding `_test.go` files and `tests/openbao_runtime_acceptance.py`; modify `setup.go`, `hostconfig.go`, `main.go`, `doctor.go`, `bootstrap.sh`, `bundle.sh`, `docs/setup.md`, `docs/openbao/docs/openbao/deployment.md`, `first-run-setup.md`.

**Steps:**

## Migration and rollback checkpoints

| Checkpoint | Safe stop / rollback |
|---|---|
| Before service bootstrap | Existing host unchanged; provider migration is not selected automatically. Remove only newly created empty test/service artifacts after exact ownership checks. |
| Vault initialized, before credential cutover | Preserve data and initialization identity. Disable routing/service if needed without deleting its volume. Continue recovery with original ceremony; never “fix” by reinitializing. |
| References prepared, before activation | Legacy consumers still use original sources; discard only unactivated metadata under the migration ID. Do not leak a new plaintext config backup. |
| Cutover completed, source retirement pending | Roll back through explicit verified migration plan; no background fallback. Keep new vault values protected and do not replay already completed external writes. |
| Legacy sources retired | Restore encrypted recovery artifacts if authorized or re-enter/rotate credentials; rolling back the binary alone cannot recover deleted files. |
| Registry/schema update | Back up generation and journal; reject incompatible downgrade. Preserve immutable IDs. Do not reconstruct associations from current paths. |
| UI/skills update | Restore previous built assets or Devkit-owned skill/block version only; preserve user edits and do not roll back authorization protections. |
| Cleanup destroyed data | No live undelete; recovery from retained backup is a separate privileged restore with privacy/identity reconciliation. Never promise purge removes old backups. |
