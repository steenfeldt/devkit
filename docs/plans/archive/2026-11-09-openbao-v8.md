## Behavior and compatibility

- Entry types: `value` (the existing default) and `login` (username/password together in one KV version). Existing entries keep their format, names and values. Do not silently pair or rename them.
- Login names are descriptive labels, not usernames. Username and password are both protected values: never include either in list/context/history, registry, audit metadata or routine output.
- CLI extends existing operations with `--type login`, `--field username|password`, and optional paired `--username-env NAME --password-env NAME`. Hidden prompts or JSON stdin carry values, never arguments. Generate creates a random password for a supplied username; rotate preserves the existing username and environment mapping. Explicit reveal selects exactly one field.
- A login optionally maps its fields to two distinct, validated environment names. Unmapped logins remain available for copy/reveal and are skipped by `secrets run`. Detect effective environment-name collisions and reserved names before executing the child. Never guess or overwrite another credential's mapping.
- Inheritance selects the whole entry: worktree > branch > project. Type changes under an existing effective name are rejected; use a new name. CAS/version checks, recoverable delete/restore, retirement and permanent purge apply to the whole entry.
- Registry schema 1 stays readable. The first login write upgrades it to schema 2 so older binaries fail closed rather than corrupt typed entries. Schema 2 retains the same IDs. Reconciliation restores type/mapping metadata from the verified KV operation. Restoring an older binary after login creation cannot resume project-secret writes; use a compatible binary or an explicit matching vault/registry recovery.
- UI offers Single value/Login, protected username/password inputs, password generation, optional environment mappings, separate username/password copy/reveal controls, and one row/count per entry. Preserve timed clearing, context/logout cancellation and same-scope write/restore safeguards.
- Update Codex/Claude bundled skill guidance; preserve user-edited installed assets. No changes to T3, Git lifecycle, unseal, cleanup preferences, service credentials or existing secrets.
