# OpenBao Lite implementation plan v9 — guided first-run setup

Status: implemented and verified locally; not deployed. User authorized continuous setup on the existing branch; do not contact or modify the running Devbox. Preserve all v8 requirements and [acceptance evidence](2026-11-09-openbao-v8.md).

## Design

`devkit setup` starts OpenBao, then coordinates the existing terminal-only init, unseal and provision operations directly. Ask for share count/threshold (defaults 1/1), display recovery material only through the existing controlling-terminal path, ask the user to confirm off-host custody, collect shares through hidden prompts until unsealed, and provision admin/backend only when required. Continue DNS, HTTPS, dashboard and skills in the same setup invocation. Never retain recovery secrets or pass them through arguments, ordinary stdout or jobs.

Resume using live seal state and backend authentication; never reinitialize an initialized vault or reset a working admin login. Preserve explicit standalone vault commands for recovery. `--yes` may continue on a ready configured vault but must stop before human-dependent operations. API/network failures stop setup before DNS credential collection. Request deadlines do not include human input time.

Reuse terminal operations rather than duplicate provisioning or automatically retain recovery material. This changes the setup orchestration, not the trusted-user model, storage, Git, cleanup or certificate architecture. v9 supersedes v8 only for the previously manual setup handoff. See [ADR 0015](../../adr/0015-guided-openbao-setup.md).
