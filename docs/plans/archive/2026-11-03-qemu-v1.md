# QEMU inventory — version 1

## Agreed behavior

Add a Virtual machines tab alongside Docker previews, and `devkit vms [--json]`.
Discover running standalone QEMU processes and active libvirt domains in the devkit
user's session and system connection. Support graphical SPICE/VNC and headless
`-display none` / `-nographic` guests (including localhost SSH host forwarding).
Deduplicate libvirt domains against QEMU by UUID. Inventory is read-only: no guest
lifecycle, disk modifications, authentication changes, or public tunnels.

Show an accessible display/headless icon and label, source, state, configured RAM,
vCPUs, disk capacity, graphics adapters and host CPU/resident-memory usage. Unknown
values stay explicitly unavailable; do not substitute zero. CPU is percentage of
one host core (may exceed 100%); RSS is host process memory, not guest used memory.
GPU utilization is unavailable. PCI devices are only identified as GPUs when host
PCI class information confirms it. Configured display endpoints are not health checks.

Connection instructions use private SSH forwarding to loopback display/SSH ports.
Never invent guest usernames, private key paths or guest IP addresses. Guest SSH
commands prompt for a username; SSH host-key checking remains enabled. For headless
libvirt domains also offer `virsh console` through SSH (guest console setup required).
TLS-enabled, Unix display sockets and unsupported listener addresses get an explanation.
No raw process arguments, disk paths, passwords, serial logs or full XML in API output.

Optional `bootstrap.sh --qemu` installs native-host QEMU/KVM, libvirt, image tools,
UEFI and software TPM prerequisites on Ubuntu/Debian and Fedora. Normal bootstrap
keeps its existing behavior. Display clients are documented separately. Use distro
package/socket defaults; do not change socket permissions or open display ports.

## Acceptance and limits

- Standalone headless and SPICE guests both appear with usable private instructions.
- libvirt session/system guests deduplicate, failures do not hide standalone guests
  or break Docker. External probes are bounded, noninteractive and read-only.
- Missing tools, permission-denied process metadata, unsupported disk formats/launch
  forms and first CPU sample are described honestly. Filesystem disks support raw
  and qcow2 via qemu-img; firmware and CD-ROMs are excluded. No storage probing over
  arbitrary network URLs. Advanced block graphs and guest memory/GPU telemetry are
  outside this initial inventory.
- Empty, populated, failure and narrow-screen UI states work; command values escape
  shell and HTML contexts. No public listener or Cloudflare mutation is introduced.

Sources: local launch scripts (read-only); QEMU system invocation documentation;
libvirt virsh/domain XML documentation; Fedora virtualization docs and Ubuntu
server libvirt docs. User refinements (headless, sizes, CPU/GPU and usage) are included
in this first written version; no earlier written plan is superseded.
